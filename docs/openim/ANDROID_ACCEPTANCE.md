## 本机复现

使用项目要求的 Yarn 4。Java 17、Android SDK/NDK 已安装；仅安装真机工具，没有安装模拟器。SDK 平台包名为 platforms;android-37.0，Build Tools 为 37.0.0，NDK 为 27.1.12297006，CMake 为 3.22.1。

在 example 中生成原生工程（不要手工修改生成目录）：

```sh
yarn expo prebuild --platform android --no-install
```

在生成的 android/local.properties 中设置本机 sdk.dir，然后构建：

```sh
export JAVA_HOME=/opt/homebrew/opt/openjdk@17/libexec/openjdk.jdk/Contents/Home
cd example/android
./gradlew app:assembleDebug -PreactNativeArchitectures=arm64-v8a -PreactNativeDevServerPort=35881 --max-workers=2
```

APK：example/android/app/build/outputs/apk/debug/app-debug.apk。它是调试包，需要电脑上的 Metro 服务，并非脱离电脑独立运行的发行包。

另开终端，在 example 目录启动 Metro：

```sh
yarn expo start --host localhost --port 35881 --max-workers 2 --clear
```

回到仓库根目录执行以下安装命令。手机开启 USB 调试并允许电脑；部分系统自动操作还要求 USB 调试（安全设置）。安装、转发及启动（多设备时显式指定 adb -s）：

```sh
export PATH=/Users/czzz/Library/Android/sdk/platform-tools:$PATH
adb install -r example/android/app/build/outputs/apk/debug/app-debug.apk
for port in 35881 10008 10002 10001 10005 37880 37881; do
  adb reverse tcp:$port tcp:$port
done
adb shell am start -n com.anonymous.example/.MainActivity
```

USB 转发使手机的 127.0.0.1 能访问本机服务；不必开放本地 Docker 的局域网端口。音视频的实际媒体通路仍须独立验收，不能仅凭信令端口连通判定成功。拔线或重启后应检查并重新建立转发。

仅使用独立 QA 账号，本轮账号密码不提交仓库；原有体验账号和群不参与破坏性测试。

开发模式修改源码后，Fast Refresh 曾使原生 SDK 的旧会话未能恢复；正常结束并重启本测试应用后，保存会话自动登录成功。重新插拔 USB 会清空 adb reverse，需先恢复转发再启动应用。

## Android 补验与修复（2026-11-16）

使用同一台 Android 14 真机、独立 QA 账号和新建测试群，不操作原有体验账号、群与消息。视频仍由用户自行测试。

### 已确认的实际流程

- **相册图片**：将仓库自带图标放入测试相册，通过系统照片选择器选择，发送后显示图片缩略图和成功标记；全屏图片预览及关闭通过。这次是真正图片消息，不是 PNG 文件消息。只选择自建测试夹具，不使用个人照片。
- **录音发送、播放与取消**：系统麦克风授权后，在 QA 单聊录制短语音并成功发送；点击播放后捕获到暂停按钮和语音播放器状态。左滑取消时先捕获到实际录音状态，结束后恢复输入栏且没有新增语音消息。没有进行视频录制或通话媒体验收。
- **群管理**：新建群 1401838190，邀请 QA 好友，群名与公告保存读回；全员禁言及解除、成员禁言及解除、管理员设置及撤销均读回正确状态；群主转让后当前账号显示普通成员，对端显示群主。当前账号实际退出后，对端用普通 QA 用户 API 重新邀请并转回群主，手机再次读回角色。最终仅此新群被实际解散。
- **破坏性操作确认**：解散确认的取消按钮与 Android 返回键都保留群；重新打开并确认后才解散，返回列表显示暂无群组。

- **个人资料**：只修改独立 QA 昵称，保存后读回；选择同一测试图片，经系统裁切确认后上传头像，页面显示“头像已上传并保存”。
- **草稿**：在 QA 会话输入未发送文本，结束并重启应用，会话列表和输入框仍能恢复草稿；随后清空，不发送。
- **附件故障恢复**：仅移除手机至本机对象存储的 USB 转发，其他服务保持运行。已解散的新建 QA 群中的失败待办重启后恢复，取消后待办记录归零。随后在明确核对的 QA 单聊发送另一份唯一内容文件，上传失败后恢复转发并重启，出现恢复提示；点击继续发送成功，持久化待办记录归零。第一次检查时误把群待办与单聊界面对比，核查记录后确认不是数据丢失；没有因此修改持久化实现。

- **归档与导航**：QA 单聊归档后在归档列表中可见，取消归档后恢复；搜索 QA 消息命中并跳回原消息；媒体汇总展示真实测试图片/文件，查看原消息可返回聊天。
- **其他确认入口**：仅对已解散的新建 QA 群会话打开删除确认并取消，会话行保留；“我的”退出登录确认取消后，QA 账号仍已连接。

### 本轮修复

长群详情页的确认卡原来追加在页面末尾，点击退出后确认内容落在屏幕外，容易误以为按钮没有响应。共享 Confirm 改用 React Native Modal，保留原卡片颜色、按钮和文字样式，限制高度并允许内容滚动；取消和 Android 返回不会提交，处理中禁止关闭和重复操作。调用处将请求错误传入确认浮层，避免失败信息被遮罩挡住。个人退出登录和会话批量删除去掉重复外层 Modal。

补充 `yarn test:im-ui` 可重复运行示例应用 UI 测试。修复先由旧实现缺少浮层的失败测试复现，修复后确认浮层、按钮、返回、忙碌和错误重试用例通过；真机再次验证居中确认和实际解散结果。
