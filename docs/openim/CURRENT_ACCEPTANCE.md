## 2026-11-19 多语言：简体中文与英文

App 的所有界面文字改由文案表提供，支持简体中文和英文，默认跟随系统语言（系统语言不是中文或英文时显示简体中文）。「我的 → 语言」可关闭跟随系统、固定一种语言；切换立即生效，不重新登录，也不离开当前页面。方案文档：Claude 文档「XIM 前端多语言方案」。

- 文案表：`features/im/i18n/zh.ts`（基准，约 790 条）和 `en.ts`，键为 `<模块>.<含义>`，`{name}` 为参数，英文复数用函数写在表里。`en.ts` 的类型由 `zh.ts` 推出，缺一条类型检查不过；`translate.test.mjs` 还检查两表键一致。翻译函数沿用组件库 `src/i18n.ts` 的做法自写，不引入 i18next；只新增依赖 `expo-localization`（读取系统语言）。
- 写法：页面里 `const tr = useT()`，`tr('key', { 参数 })`；变量名用 `tr`，因为 `t` 已是主题。`tr.locale` 是当前语言的日期标签（`zh-CN` / `en-US`）。
- 语言保存在 `ui/preferences.ts`（键 `openim.product.language`），与主题、壁纸、深色模式同一套。聊天组件库的 `locale` 和 App 覆盖的 `labels` 跟随当前语言。
- 底层只交出代码：应用状态里的连接状态改存代码（`connecting`、`connected`、`offline` 等），报错改存失败本身；底层抛 `ProductError(key)`；生成文字的函数（`toMessage`、`toChat`、`shortTime`、`messageTimestamp`、群禁言说明、通话说明等）把 `tr` 作为参数。保存到本机的内容（退出原因、待发送附件的错误）存键，不存文字。
- 报错只有一个出口 `shared/error-message.ts`：App 自己的失败按键翻译，服务端和 SDK 的失败按 `errCode` 翻译（`serverError.<码>`），不认识的显示通用提示，服务端文字一律不显示。chat 接口封装统一抛 `ServerError`（保留 `errCode`）；通话模块原来自己的 `safeCallErrorMessage` 已删除。

## 2026-11-19 添加好友：按邮箱、手机号查找

添加好友的搜索框除了完整用户 ID，也接受完整的邮箱或手机号（`contacts/contact-query.ts` 判断类型）：含 `@` 的是邮箱；11 位 1 开头的号码（可带 `+86`/`86`、空格、横线）是中国大陆手机号；`+区号 号码`（区号后要有空格或横线）是其他国家手机号；其余都按用户 ID 查。只做精确匹配，不支持部分邮箱或号码，避免被用来枚举用户。找不到时提示对应的「请检查邮箱/手机号是否完整」。像手机号的输入若没有人用这个号码，还会再按用户 ID 查一次（管理员可以自定义 ID，以前能按 ID 找到的人不会因此找不到）。

- 服务端（chat 仓库 perf）新增 C 端接口 `POST /user/find/contact`，按现有接口的写法：`chat.proto` 的 `FindUserByContactReq{email | areaCode+phoneNumber}` / `FindUserByContactResp{user}`、`Check()` 要求邮箱和手机号二选一、RPC `FindUserByContact`（账号凭证表精确查找，手机号凭证为 `区号 号码`）、`a2r.Call` 处理器、`/user` 路由组（需 chat token）。返回的是公开资料，非管理员看到的对方邮箱为空；没找到时 `user` 为空而不是报错。凭证表里也存着账号名，所以要求凭证类型与查找方式一致：把某人的账号名当邮箱传过来不算匹配。
- 客户端：`infrastructure/openim/contact-lookup-api.ts` 按 `self-profile-api.ts` 的方式调用（chat token、15 秒超时、`errCode` 检查），只取回用户 ID；之后与输入用户 ID 一样经 OpenIM SDK 读资料和好友状态。
- 暂不提供"不允许别人通过邮箱/手机号找到我"的隐私开关。
- 验证：本机测试环境的 openim-chat 换为含新接口的镜像 `local/openim-chat:perf-contact` 后，用接口直接测了：找到 bob（返回的邮箱为空）、不存在的邮箱和手机号返回空、同时传邮箱和手机号报参数错误、无 token 被拒。网页手机宽度用 alice 实测：按邮箱找到 Bob、Charlie（均显示已是好友），手机号 `138 0013 8000` 显示「未找到该用户 / 请检查手机号是否完整」。QA 账号都没有手机号，找到手机号用户的情况只有单元测试覆盖；Android、iOS 未实测。

## 2026-11-18 通话进主导航、返回修复、登录与断网处理（`ec1796f`…`4420c81`）

1. PC 分区标题（消息、通话、通讯录、我的）与手机一致，统一为 18/600，样式在 `primitives/styles.ts` 的 `pageTitle`。

**登录与断网（用户定的规则：不是 token 问题就进入 App；是 token 问题才回登录页）**

5. 不是 token 问题（网络、超时、服务不可用）：保留会话进入 App，显示缓存的会话列表，状态条、页面报错和操作报错只说"网络异常，无法连接服务器"，并自动重连（2 秒起，翻倍，最长 30 秒；下拉或重新加载立即重试）。
   - **这推翻了下方 11-17"产品启动页与首屏缓存"一节中"恢复期间不伪造已认证 session"的约定**：现在断网时 `session` 已设置，但 SDK 并未登录，由 `offline` 标记和统一的网络提示兜住。
   - Web 端 SDK 断网也能"登录成功"、只在后台重连，之前每次本地刷新都会把状态改回"已连接"；现在状态只跟随 SDK 的连接事件。
6. 是 token 问题：回到登录页，自动填好上次的邮箱和服务器地址（不保存密码），只需输入密码。"重试恢复上次登录"按钮及其状态已删除。
   - 认定为 token 问题的只有服务端明确的 token 错误码 1501–1507（`auth/sdk-login-error.ts`），以及 SDK 的过期、失效、被挤下线事件。其余错误一律按网络处理，保持原设计"拿不准就不删数据"的原则。
   - 账号在 Android、iOS 上存于设备；Web 上与登录信息一样按标签页保存，新标签页不会预填。
7. 原生端 JS 重新加载（Metro、热更新）后，SDK 仍保持上一次登录，再次登录被拒，被误判为网络异常（即 11-17 页面审计中"热更新期间出现'暂时无法连接服务'"的原因）。现在同一账号已登录时直接视为已登录。
